How to use this page

Step 4 asked every model the same 8 questions about every skill you picked in Step 3. One row here is one skill; open it to compare the answers.

Workflow

  1. Click a skill row. The details panel opens below the table.
  2. Pick a prompt (P1 to P8), then a model. The answer is shown rendered; switch to Raw to see the exact text that was stored.
  3. Compare the same prompt across models, or the same model across prompts, to see where a model is weak.

The 8 prompts

They are 4 pedagogical categories with 2 prompts each, so answers can be judged per category and not only per single question. The levels follow the revised Bloom taxonomy.

  • C1 Conceptual Explanation (Understand): P1 for a beginner, P2 for a technical student.
  • C2 Practical Application (Apply): P3 in an organisation, P4 in daily professional work.
  • C3 Sustainability Rationale (Analyse, Evaluate): P5 the contribution, P6 the benefits and limitations.
  • C4 Instructional Design (Create): P7 a learning path, P8 a teaching scenario.

Columns

  • Category (G1 to G8): the group of the skill, from Step 2.
  • Prompts and Models: how many were collected for that skill.
  • Status summary: how many answers came back, failed, or came back empty.

How to use this page

Every answer collected in Step 4 gets four scores from 1 to 5. Several people can rate the same answers, which is what makes inter-rater agreement possible, so each rater works under their own name.

Workflow

  1. Type your name. Scores are kept per rater and stay in this browser until you export them.
  2. Score the answer on screen, then Save and next. Rated answers drop out of the queue, so you can stop and come back later.
  3. Export ratings downloads ratings_<your name>.csv. Save it in evaluate/output_evaluate/, then run python evaluate/stats.py.

The four criteria

  • Clarity: understandable, well structured, accessible.
  • Depth: connects the skill to real context and sustainability reasoning.
  • Relevance: actually answers about the intended ESCO skill.
  • Pedagogical value: guides the learner with steps, examples and reasoning.

Keyboard

Press 1 to 5 to fill the next criterion that has no score, and Enter to save and move on.

The rubric is provisional. Scores are stored in this browser only, so export before clearing browser data or changing computer. Use Load ratings CSV to continue from an exported file.

How to use this page

Besides the people, the models can score the answers. Produce the data first, from the project root folder:

  1. python evaluate/judge.py to score everything.
  2. Press Reload here.
  3. python evaluate/stats.py for the full report, including the comparison with the human raters.

Why every judge scores every answer

Including its own. A model asked to grade only its own work tends to score it high, and that inflation cannot be measured when there is nothing to compare it with. Because every judge sees every answer, each judge's score on its own answers can be set against what the other judges gave the same answers, which is the Self-preference figure below. The judge is never told which model wrote the answer.

Read the warning first

If a judge gave nearly the same score to every answer, it is not rating anything, and its means look perfectly normal while meaning nothing. The red box appears when that happens. It is a real risk with small models.

An LLM judge does not replace human rating. It is a second opinion whose own reliability has to be reported next to it.
